## 逐项依据

### 1. 内容完整与忠实度 · 19 / 20

- 静态审计：小节 27、演示 27、术语 25、搜索索引 126，**待修复项 0**。
- 27 个演示逐个跑通，且演示代码与原站逻辑一致（`build.py` 从 `tools/origin/` 快照重抽，不是手工抄写）。
- **扣 1**：`supplementary/` 仍有 9 处旧式（非 module）`<script src>`；讲义 PDF 原样保留。这两条都写在「遗留与取舍」里，属于有意妥协，但确实不是「全站统一」。

### 2. 信息架构与导航 · 11 / 12

- 四块内容各有明确职责：学习路径（我该走哪条路）、知识图谱（这章有哪些概念）、全部章节（目录）、怎么用。
- 顶栏导航顺序 = 版块顺序，滚动高亮用 rAF 节流；1080 只留前两项、720 全隐。
- 门户首屏是「可视化工作台」，不是三列清单；章节微缩图、统计条、学习路径关卡图都在首屏内可见。
- **扣 1**：学习路径与知识图谱两处的引导语仍在解释同一件事（「不知道从哪开始就先看路径」），信息有轻微重复。

### 3. 视觉与设计系统 · 13 / 14

- 131 个 CSS 变量，三层：原始色阶 → 语义令牌 → 组件；改一处主题色不需要翻六个文件。
- 配色采用 Wong（Nature Methods 2011），课程讲色彩与色觉缺陷，站点自己就是那个标准的示例 —— 这种「内容与载体互证」的做法加不少分。
- **扣 1**：演示模块（从原站抽取）里仍有 `#4338ca`、`#f8fafc` 这类硬编码色值，深浅色下靠 `content.css` 兜底，没有走令牌。

### 4. 实现质量与正确性 · 19 / 20

- 真实浏览器：35 个页面零控制台报错、零失败请求；交互与布局断言 **40/40**。
- 本轮修掉两个一直没人点到的老 bug：
  - 第 1 章「函数」演示选 `reduce` → `[...out]` 抛 `out is not iterable`，输出区整块空掉；
  - 第 3 章「对错案例」演示点错误选项 → `classList.add("")` 抛 `DOMTokenList` 异常，**投错票毫无反应**。
- 两个 bug 都改在可重建的地方（`build.py` 的 `DEMO_PATCHES`，正则必须**恰好命中一次**），不是改生成物。
- **扣 1**：演示模块本质仍是「快照 + 正则补丁」，原站源码一改就得同步调补丁。这一轮正好印证了这一点——补丁表已经从 2 条长到 11 条，每一条都是原站演示里一个真实的错。
- 补充：评分后按「点一遍看画得对不对」的方式复查，又发现并修掉 7 处画布裁剪、2 个「一个数据都没画」的演示、4 组完全没有样式的类名（详见文末）。这部分若按评分时的状态计算，本项应为 17。

### 5. 国际化 · 7 / 8

- 正文是双 DOM + 一条 CSS 规则切换，禁用 JS 时默认中文仍可读。
- 本轮补齐两个缺口：
  - 演示区新增运行时双语层：词典 522 条，**演示代码一个字没改**；EN 模式下演示区零中文（代码块的中文注释也翻了），切回中文完整还原；
  - 术语表 25 条英文释义从「一句话摘要」扩写到与中文等深，并加审计规则防止再退化成半句。
- **扣 1**：数据集里的人名、地名虽然是拼音英译，`.console` 里的 JSON 输出仍保留中文字段值（那是程序真实输出，不宜篡改）；深度本地化（日期格式、术语地域差异）没做。

### 6. 可访问性 · 7 / 8

实测（门户 / 第 1 章 / 术语表三页）：`h1` 唯一、标题无跳级、空链接 0、空按钮 0、无标签输入框 0、缺 alt 图片 0、焦点环 `2px solid` 可见、`main/nav/header/footer` 地标齐全、`aria-*` 共 906 处。

- **扣 1**：没有接 axe / Lighthouse 做自动化无障碍扫描，也没有跑完整的键盘操作流程（Tab 顺序、焦点陷阱）与真实读屏测试。

### 7. 响应式与性能 · 8 / 9

- 6 类页面 × 3 档窄屏（390 / 768 / 1024）共 18 个组合零横向溢出，含知识图谱与关卡图容器内不横滚。
- 门户首屏原始 339 KB、**gzip 后 97 KB**；`d3.esm.js`（280 KB）实测**滚动到知识图谱才请求**，首屏不为第二屏的图买单。
- **扣 1**：门户仍有 4 个同步脚本、6 张样式表，HTTP/2 下尚可，离「关键 CSS 内联 + 脚本 defer」还有一步。

### 8. 工程化与可复现 · 8 / 9

- `build.py`（2993 行）一条命令从原站快照重建全站；`audit.py`（924 行）静态审计；`verify_render.mjs`（1350 行）真实浏览器断言。
- 规则都带「为什么」：每条断言、每条补丁都写了它守的是哪个曾经真实发生的事故。
- 本轮新增的自检：词典键必须含中文、值不许含中文、数字占位数量对得上；术语英文不许短于中文；词典文件缺失或被截断会被审计抓到。
- **扣 1**：三件套靠手动跑，没有 CI（GitHub Actions）；`verify_render.mjs` 全量跑一次约 3 分钟，提交前容易偷懒。

## 评分之后又扫出来的一批 bug（已全部修掉）

补完两个缺口后，按「不只看有没有元素，还要看画得对不对」的方式把 27 个演示逐一复查了一遍。
下面这些的共同点是：**不报错、不空白、既有断言全绿**，只是东西被裁掉了或者根本没画。

| 问题 | 数量 | 后果 |
|---|---|---|
| 演示自己拼的类名在样式表里不存在 | 4 组（quiz / attr / color / cvd） | 投票卡竖着摞成一列；时间属性卡片没有布局 |
| Map 用 Date 建键、用字符串查询 | 2 个演示（5.3 / 5.4） | 日历热图整张一种颜色；螺旋图全灰 |
| 内容画到 `<svg>` 框外被裁 | 7 处 | 树标签、金字塔底座、Lab 轴标签、日历的 12 月、CVD 缩略图、投票缩略图 |
| `selectAll("text")` 抢走坐标轴刻度 | 1 处（第 1 章 3.3.3） | x 轴刻度变成人名，左侧姓名标签只剩一个 |

修完后新增两条断言，专门盯这一类「画错了但不报错」：**画布内容不得超出画布**、**日历热图必须
至少 30 种颜色**。前者一加，7 处裁剪当场全暴露——这也是这次能一次性扫干净的原因。

这件事本身也说明了评分口径的局限：**「35/35 页面干净 + 33/33 断言通过」只能证明没有抛错，
证明不了画出来的东西是对的。** 所以第 4 项维持 19 分而不是 20：防线补上了，但防线是被这道伤
教会才补上的。
