## 二、原站体检：问题都是量出来的，不是感觉出来的

动手前先对 5 章 HTML 快照做了静态体检，结论如下（全部可复现）：

**1. 页面编辑器残留 1615 处。** `data-page-node-id="KWCKPox71SaHV20QEiPanl"` 这类属性遍布每个标签，对渲染毫无作用，只让 HTML 变胖、让 diff 变吵。其中还有 3 处同一标签重复属性，属于非法 HTML。

**2. 双语靠「中英段落并排堆叠」。** 每一段中文后面紧跟一段英文，两段都在 DOM 里、都参与排版，英文段落再被 JS 遍历加 `hidden`。**中文读者每次要读两遍内容。** 这与「更清晰」的目标正好相反。

**3. 可访问性近乎空白。** 全站 5 个 `aria-` 属性、0 个跳转链接、0 个 `:focus-visible` 样式、0 个 `prefers-reduced-motion`。键盘用户和读屏用户基本无法使用。

**4. 代码块只是「灰底的 `<pre>`」。** 60 个 `<pre>`，没有语法高亮、没有行号、没有复制按钮。原作用 ⭐ 标记了 123 处「必须掌握的编程点」，但视觉上无法区分。

**5. 无搜索。** 5 章内容跨 27 个小节，学生想找「d3.rollup 怎么用」只能靠翻。

**6. 无学习导航。** 没有学习目标、前置知识、预计时长、章内进度。

**7. 外壳复制了 5 份并已漂移。** 每章各有一套顶栏/侧栏/tab/分页，5 套 CSS 分别 10~26 KB，同一个组件在 5 个文件里有 5 个略有差异的实现。

**8. 死链 10 类。** 详见第五节。

**9. 无 `<meta description>`、无 OG 标签、无 favicon、无 404 页。**

**10. 无深色模式。** `prefers-color-scheme` 出现 0 次。

**11. 断点只有 640px 一档。** 平板（768~1024）区间没有专门处理，宽表格在窄屏直接横向溢出。

## 三、核心方案：把「内容」和「外壳」拆开

原站是 5 个 40~90 KB 的手写 HTML，里面混着三类东西：

1. **正文内容** —— 作者的劳动成果，**必须一字不改地保留**
2. **页面编辑器残留** —— 1615 处无用属性
3. **每页各自一套的外壳** —— 重复了 5 遍，且已经互相漂移

手工改这 30 万字符既慢又必然漏改。所以做法是：**写一个内容管道（`tools/build.py`），从原站快照里只抽取内容，再用统一外壳模板重新装配。**

这样带来三个好处：

- **内容零改写**：原作者写的每一段讲解、每一个 ⭐ 关键点都原样保留（抽取时用带语言栈的标签扫描来数 ⭐，避开中英双份重复计数）；
- **外壳只有一份**：改导航、改配色、加深色模式只改一处；
- **可复现、可 diff**：`python tools/build.py` 重跑一次得到完全相同的产物。

配套的还有 `tools/build_supp.py`（修复与统一补充 Demo）与 `tools/audit.py`（全站静态审计）。

## 四、具体改了什么

### 4.1 双语：从「两段并排」改成「双 DOM + CSS 切换」

原站把中英两段都渲染出来，再用 JS 遍历所有元素加 `hidden` —— 首屏会闪、遍历成本高、且中文读者视觉上被英文段落打断。

**改成**：中英两版同时存在于 DOM，用 `html[data-locale]` + 一条 CSS 规则切换：

```css
html[data-locale="zh"] [data-lang="en"],
html[data-locale="en"] [data-lang="zh"] { display: none !important; }
```

好处：切换零 JS 遍历、无闪烁、首屏渲染前内联脚本就已定好语言、搜索索引和术语表也能按语言分别检索。切换按钮状态、`<html lang>` 属性同步更新（影响读屏发音与断行）。

### 4.2 代码块：从「灰底 pre」升级为「可读的代码」

- 用 `::before` + `attr(data-ln)` 生成行号，**不污染可复制文本**
- 关键行（原作者用 ⭐ 标记的 123 处）加黄色左边条 + 浅底
- 每个代码块加语言标签、关键点计数、复制按钮
- 语法着色基于原有的语义标记做**渐进增强**——禁用 JS 仍是一份可读的 `<pre>`

### 4.3 信息架构：补上「学习导航」这一层

原站直接给内容，学生不知道「这一章要学什么、要多久、学之前得会什么」。新增：

- **学习目标卡**：每章 5~6 条，用「你应该能够……」的可检验句式（共 26 条）
- **前置知识**与**预计时长**
- **概念依赖图**：每章一张分层有向图，讲清「先理解 A 才容易理解 B」。自研约 6 KB 渲染器，**没有为门户页引入整个 D3（省约 280 KB）**
- **术语表**：25 个术语，每个除了「是什么」还写了「为什么重要、容易在哪儿搞错」——名词表最容易变成背了也没用的清单

### 4.4 检索：命令面板式全站搜索

`Ctrl/⌘+K` 或 `/` 唤起。索引 86 条，覆盖章节正文、关键代码、术语。索引**按需加载**（没打开过搜索的读者不付这次请求），极简相关度打分：标题前缀命中 +60、词中 +34、正文 +12。

### 4.5 进度：小节级阅读记录

读过的章节在侧栏打勾、显示百分比；门户页的章节卡显示「继续 · 已读 X / Y」，回到站点时能直接接着看。

### 4.6 演示：从「全部预加载」改成「按需加载」

原站每章的演示代码写在 `lesson.js` 里，进页面就下载、就执行。现在拆成 5 个独立模块 `assets/js/demos/ch0X.js`，**只有学生真的点开「演示」tab 才动态 `import`**。

同时修掉一个原站隐藏 bug：5 章演示键名互相冲突（第 1 章和第 3 章都有 `d-3-1`），因为都挂在全局 `window.DEMOS` 上。抽取时把注册表收进模块作用域，冲突消失。

### 4.7 视觉系统：用设计令牌，且配色本身就是课程内容

- **设计令牌分层**：原始色阶 → 语义令牌 → 组件，共 128 个 CSS 变量。改主题只动语义层。
- **配色采用 Wong 色板**（Nature Methods 2011），色觉缺陷友好。第 3 章正好讲「色彩与色觉缺陷」——**网站自身的配色就是课程内容的示范**，学生在读第 3 章时，正在看的界面就是那个标准。
- **科技感但不过度**：顶栏毛玻璃 + 门户头部用 `linear-gradient` + `mask-image` 做的坐标网格（呼应「可视化 = 坐标系」），章节卡悬停时右上角淡出主色块。所有装饰都 `aria-hidden`，不干扰信息传递。

### 4.8 门户页：让首页自己会说话

改到这里被提了一句「首页全是文字」。查下来根因是构建脚本的一处疏漏（见 4.10 第 7 条），但也确实点出一个设计问题：**这是一门讲可视化的课，门户页却完全靠文字介绍自己**。

于是给每张章节卡片加了一枚**主题微缩图**：

| 章 | 图形 | 想传达的 |
|---|---|---|
| 1 · 数据 | 四列表格，表头着色 | 数据的本质是「带类型的属性表」 |
| 2 · 流程 | 四段节点链 + 箭头 | 数据在阶段之间流动 |
| 3 · 色彩 | 色相带 + 明度渐变带 | 色彩空间的两个基本轴 |
| 4 · 低维 | 散点 + 坐标轴 | 按量级分组、看趋势 |
| 5 · 时序 | 折线 + 面积 | 变量在时间轴上的走势 |

三条实现约束：

1. **纯内联 SVG、构建期写死**（`tools/build.py` 的 `CHAPTER_MOTIFS`）——不发额外请求、不依赖 JS，禁用脚本时图形依然在；
2. **取色一律走 `--viz-*` 令牌**（就是 Wong 色板，明暗两套主题各有提亮版本），线条用 `currentColor + opacity`，因此**切主题时图形自动跟着换**；
3. 只作视觉指引，语义仍由卡片文字承载，所以整体标 `aria-hidden`，读屏软件不被这些装饰打扰。

### 4.9 可访问性与响应式

| 项目 | 做法 |
|---|---|
| 键盘 | 全部交互可达；`:focus-visible` 统一焦点环；命令面板有焦点陷阱；搜索/小节切换/翻章都有快捷键 |
| 跳转链接 | 每页首个可聚焦元素是「跳到主要内容」 |
| 读屏 | 831 个 `aria-*`；概念图、演示区带 `role="img"` + `aria-label` |
| 动效 | 尊重 `prefers-reduced-motion`（5 处），关闭后所有过渡降到 1ms |
| 断点 | 5 档（1080 / 900 / 720 / 640 / 480）。宽表格在窄屏转卡片态，用 `td::before { content: attr(data-label) }` 保留字段名 |
| 触屏 | ≤900px 时图标按钮从 32px 放大到 40px，减少点偏 |
| 打印 | 打印时三个 tab 全部展开——讲义可以直接打印成一叠 |

### 4.10 顺手修掉的 10 个 bug

前 6 个都是「静态看着没问题、点开才是坏的」，靠 `tools/verify_render.mjs`（真实浏览器跑全站）才抓出来。第 7 条反过来——它连「点开看元素」都看不出来，是看截图才发现的。第 8~10 条是上线后用户点「演示」反馈才暴露的：

| # | 问题 | 症状 | 原因 |
|---|---|---|---|
| 1 | 章节页导览按钮缺失 | 搜索、进度全部静默失效 | `Tour.init` 绑定 `#tour-play`，而该按钮只写在门户页；一行 `null.addEventListener` 抛异常，把同一次 boot 里排在后面的模块全部带停 |
| 2 | 搜索索引地址是页面相对路径 | 除门户页外，全站搜索都无结果 | `fetch("assets/search-index.json")` 在 `/lesson-03/` 下请求 `/lesson-03/assets/...`，404 被 `catch` 吞掉 |
| 3 | 搜索索引是分语言嵌套结构 | 输入即抛异常，列表里留着上一次空查询的残留，看起来像「搜不到」 | 索引形如 `{href, zh:{title,…}, en:{…}}`，但消费端直接读 `entry.title`，全是 `undefined` |
| 4 | 进度键格式不一致 | 读完了百分比仍是 0% | 章节页产出 `c3s1`，侧栏期待 `c03s1` |
| 5 | 滚动高亮的提前 return | 进度永远不写入 | 打点逻辑写在「当前小节变化」分支里，不换节就永远不执行 |
| 6 | 侧栏遮罩参与网格布局 | 正文宽度塌成侧栏宽度（约 272px） | 遮罩是 `.shell` 网格的第二个子项，把 `.main` 挤到第二行第一列。页面不报错、不溢出，只有量元素位置才看得出来 |
| 7 | 门户页没引用 `portal.css` | 首页所有卡片、统计条、网格全塌成一列纯文字 | 构建门户页时 `head()` 调用漏传 `extra_css=("portal",)`。因为页面**根本没请求**这个文件，所以不报 404、不报错、元素也都在，静态审计和浏览器验证当时都是「绿」的 |
| 8 | 演示模块路径拼错 | 5 章 **27 个演示全部**显示「演示没能加载」 | 页面写 `data-demo-chapter="1"`，`lesson.js` 直接拼成 `./demos/ch1.js`，而文件叫 `ch01.js`。属性值与文件名之间靠运行时补零对齐，这个约定没有任何地方写着 |
| 9 | 第 2 章演示模块重复声明 | 第 2 章演示全挂，其余章正常 | 抽取时把 `window.DEMOS = window.DEMOS \|\| {}` 换成 `const DEMOS = {}`，而该章原文件第 110 行本来就有一处 `const DEMOS = {}` → `Identifier 'DEMOS' has already been declared`，整个模块在解析阶段就失败 |
| 10 | 演示区残留与重复 | 第 1、2 章每处演示多出一个空框；第 3~5 章永远挂着一行「加载中…」 | 原站快照里带着两种旧占位：无 `data-demo-chapter` 的旧挂载点（`runDemo` 直接 return），以及 `id="demo-mount-…"` 的占位块（内容改写到新挂载点后就不再更新） |

第 8~10 条暴露的是同一个教训：**验证本身失效**。当时的断言写的是 `mounted > 0 || svg > 0`，而加载中/失败时也会插入一个 `.demo-state` 的 `<p>`——于是「至少挂载了一个元素」恒成立，演示全挂它照样是绿的。现在改成只认 `data-ready="1"`、挂载点非空、无失败请求，并且 5 章逐章跑（第 2 章解析失败而第 3 章正常，只抽查一章必然漏）。同时给 `audit.py` 加了「演示接线错误」这条静态规则：`data-demo-chapter` 必须能落到真实的 `chNN.js`，`data-demo` 键必须在模块里注册过。

修正后做了一轮**防御性加固**：

- `boot()` 里每个模块各自 `try/catch`，一个坏了只影响它自己，控制台直说哪个模块坏在哪——这类「静默级联失效」不该再有第二次；
- 静态审计新增 **`样式未加载`** 检查（见第六节）：把每个页面用到的类，逐个对照「本页实际加载的样式表」里有没有定义。上面第 7 条就是它专治的情况；
- 浏览器验证新增 **`布局成型`** 断言：不去数元素在不在，而是**量容器里出现了多少个不同的左边界**——也就是它到底排成了几列。样式一丢就会掉到 1 列，立刻失败。

| 2 | `supplementary/index.html` → `yearcalendar.html`（仓库里从来没有这个文件） | **按描述补做**：van Wijk 日历热图，2022–2025 共 1461 天，一行一年、366 格横向排开、每 7 格一条周分割线、月份边界加标签 |

| 4 | `supplementary/index.html` → `../portal/styles.css`（不存在）、`../i18n.css`（已废弃） | 重写索引页，改用站点设计系统 |
| 5 | `calendar.html` / `calendar1.html` / `calendar3.html` 用的是 `'/data/calendar_data_modified.csv'` | 站点根绝对路径，本地看着对，**部署到 `/vis/` 子路径就 404** → 改为正确相对路径 |

| 7 | `regression.html` 加载了 d3-regression、算出了回归对象，**然后什么都没画** | 这种「不报 404 但也不渲染」比断链更难发现 → 重写为真正绘制散点 + 最小二乘拟合直线，并标出斜率截距 |
| 8 | 第 1 章 `demo/` 里 5 个实验页面失去入口 | 它们是**自包含、能单独拷给学生改**的优质内容，重构后一度变成「能打开但走不到」的孤儿 → 重新接线到第 1 章页面的「延伸实验」区块 |
| 9 | 补充 Demo 缺 `charset` / `viewport`（7 个页面） | 补齐（影响手机上缩放与非 UTF-8 环境下的乱码） |
| 10 | `newstudent.html` 写 `<html lang="en">` 装的却是中文；注释里留着一行会炸的 `import * as d3 from "d3"`；`await await` 重复 | 逐条修 |

另有一个**我在修复过程中自己踩的坑**，记在 `tools/build_supp.py` 的注释里：

> `d3.csv` / `fetch` 的相对路径是按**文档**（地址栏那个页面）解析的，**不是按脚本文件**。
> `utils/data.js` 里的 `'./newstudent.csv'` 被 `supplementary/tableshow.html` 加载时，实际请求的是 `supplementary/newstudent.csv`——它一直都在。第一版误以为要按脚本位置解析，改成 `'../newstudent.csv'`，结果请求打到站点根，把两个本来正常的页面改成了 404。**是浏览器验证抓出来的，静态审计当时反而认为「改对了」。**

`404.html` 还有一个特殊问题：GitHub Pages 会把 404 页部署在**站点根**，但地址栏保留的是**缺失路径**。所以相对链接会解析到错误位置，写死 `/glossary.html` 又会指向域根。解决方式是页面里放一段极短的同步探测：从当前路径逐级向上，找第一个真能取到 `assets/css/tokens.css` 的层级。**同一段代码对「域根部署」「`/vis/` 子路径部署」「本地 `http.server`」三种情况都成立。**

## 六、怎么确认改对了：三层验证

重构最容易出现「静态看起来没问题、点开是坏的」。所以做了三层，且都可重复执行：

**第一层 · 静态审计** `python tools/audit.py`

检查 7 类问题：断链、站点根绝对路径、外部 CDN 可达性、编辑器残留与非法 HTML、图片 `alt`、内容完整性（小节数/演示数与元数据是否对得上）、以及**样式覆盖**（页面用到的类，是否真有「本页加载了的」样式表去定义它）。

其中三条规则是踩坑后加的：
- 扫描前先挖掉 HTML 注释、`<pre>` 代码示例块、JS 注释 —— 否则正文里的 `from 'a table' to 'a chart'` 会被当成 import 说明符，代码示例里的 `from 'd3-regression'` 会被当成真实依赖；
- 运行时路径的解析基准要按**加载该脚本的页面**算，并沿 import 图传播 —— 否则 `d3.csv('./data/x.csv')` 会被误判成断链；
- 样式覆盖必须拿「本页实际加载了哪几张样式表」当基准。只判断「这个类在全站有没有被定义过」是不够的：门户页漏引 `portal.css` 那次，`.chapter-card` 在 `portal.css` 里定义得好好的，问题恰恰是这个页面没加载它。

**第二层 · 浏览器渲染** `node tools/verify_render.mjs`

无头 Chrome 逐页打开 **35 个页面**，抓五类只有运行时才暴露的问题：控制台报错 / 未捕获异常、请求失败、DOM 断言（该出现的元素真的出现了）、内容断言（日历要真的画出 ≥1400 个格子，而不是「有个空 svg」）、以及**布局成型断言**。

最后一条的思路值得单说：**它不去数元素在不在，而是量一个容器里出现了多少个互不相同的左边界** —— 也就是这个栅格实际排成了几列。样式一旦丢失，任何多列容器都会掉到 1 列，断言立刻失败。门户页那次塌版就属于这一类：`.chapter-card` 一个不缺，但全在同一列上。

> 当前结果：**35/35 页面完全干净，0 报错、0 失败请求；门户页实测章节网格 3 列、统计条 5 列、使用说明 4 列，5 枚微缩图共 48 个图形。**

**第三层 · 交互验证**（同一脚本内）

6 项端到端断言：演示 tab 触发动态 `import` 并渲染（`mounted:1, svg:7`）、搜索出结果（24 条）、主题切换、中英双 DOM 切换（英文可见且中文全部隐藏）、概念图渲染（18 个图形）、**阅读进度写入并让本章侧栏显示 100%**。

另有窄屏（390×844）与打印媒体的回归检查：无横向溢出、汉堡按钮 40×40 可点、侧栏默认收起；打印时三个 tab 全部展开。

## 七、遗留与取舍

诚实说明几处**有意没做**的事：

1. **补充 Demo 里的 9 处旧式（非 module）`<script src>`** 保留了。这些页面用「全局函数 + 顺序加载」，页内自洽、能跑。改成 ES Module 要动作者的数据管线（相互依赖的全局函数），**风险大于收益**。审计脚本把它登记为「遗留说明」而非缺陷。
2. **`d3js.org` 与 `unpkg` 两个 CDN 混用**保留了原样。统一到 jsDelivr 更整齐，但会导致我改动未出问题的代码；只在 `regression.html` 上动了手脚——因为它的脚本顺序有真实 bug（见下）。
3. **`d3-regression` 的脚本顺序**：实测两个 UMD 包的挂载方式不同——d3 v7 是 `window.d3 = window.d3 || {}`（叠加，安全），d3-regression 是 `window.d3 = {}`（**无条件覆盖**）。所以必须先加载插件、再加载本体，反过来会报 `d3.scaleLinear is not a function`。
4. **仓库里另附的讲义 PDF** 原样保留，未改写。
5. **未加视频**（按要求：服务器存储空间有限）。

### 关于 404 页的一个真实坑

GitHub Pages 把这个文件部署在**站点根**，但浏览器地址栏里保留的仍然是**没找到的那个路径**。
于是页面里所有相对地址都会被按缺失路径解析 —— 访问 `/a/b/c/` 时，页面写的
`assets/css/tokens.css` 会变成 `/a/b/c/assets/css/tokens.css`，favicon、样式、脚本全部 404，
**页面变成一张没有样式的裸页**。

这个坑本地预览测不出来（本地站点根就是 `/`），是上线实测才暴露的。修法是让 404 页在
`<head>` 最前面做一次同步探测，算出真正的站点根写成 `<base>`，此后文档里所有相对地址
自动按正确基准解析，不用逐个去改。

`tools/verify_live.mjs` 就是为这件事写的 —— 部署后跑一次，确认 404 页在子路径下样式正常。
当前结果：**11/11 全部通过**。
