## 二、原站体检：问题都是量出来的，不是感觉出来的

动手前先对 5 章 HTML 快照做了静态体检，结论如下（全部可复现）：

**1. 页面编辑器残留 1615 处。** `data-page-node-id="KWCKPox71SaHV20QEiPanl"` 这类属性遍布每个标签，对渲染毫无作用，只让 HTML 变胖、让 diff 变吵。其中还有 3 处同一标签重复属性，属于非法 HTML。

**2. 双语靠「中英段落并排堆叠」。** 每一段中文后面紧跟一段英文，两段都在 DOM 里、都参与排版，英文段落再被 JS 遍历加 `hidden`。**中文读者每次要读两遍内容。** 这与「更清晰」的目标正好相反。

**3. 可访问性近乎空白。** 全站 5 个 `aria-` 属性、0 个跳转链接、0 个 `:focus-visible` 样式、0 个 `prefers-reduced-motion`。键盘用户和读屏用户基本无法使用。

**4. 代码块只是「灰底的 `<pre>`」。** 60 个 `<pre>`，没有语法高亮、没有行号、没有复制按钮。原作用 ⭐ 标记了 123 处「必须掌握的编程点」，但视觉上无法区分。

**5. 无搜索。** 5 章内容跨 27 个小节，学生想找「d3.rollup 怎么用」只能靠翻。

**6. 无学习导航。** 没有学习目标、前置知识、预计时长、章内进度。

**7. 外壳复制了 5 份并已漂移。** 每章各有一套顶栏/侧栏/tab/分页，5 套 CSS 分别 10~26 KB，同一个组件在 5 个文件里有 5 个略有差异的实现。

**8. 死链 10 类。** 详见第五节。

**9. 无 `<meta description>`、无 OG 标签、无 favicon、无 404 页。**

**10. 无深色模式。** `prefers-color-scheme` 出现 0 次。

**11. 断点只有 640px 一档。** 平板（768~1024）区间没有专门处理，宽表格在窄屏直接横向溢出。

## 三、核心方案：把「内容」和「外壳」拆开

原站是 5 个 40~90 KB 的手写 HTML，里面混着三类东西：

1. **正文内容** —— 作者的劳动成果，**必须一字不改地保留**
2. **页面编辑器残留** —— 1615 处无用属性
3. **每页各自一套的外壳** —— 重复了 5 遍，且已经互相漂移

手工改这 30 万字符既慢又必然漏改。所以做法是：**写一个内容管道（`tools/build.py`），从原站快照里只抽取内容，再用统一外壳模板重新装配。**

这样带来三个好处：

- **内容零改写**：原作者写的每一段讲解、每一个 ⭐ 关键点都原样保留（抽取时用带语言栈的标签扫描来数 ⭐，避开中英双份重复计数）；
- **外壳只有一份**：改导航、改配色、加深色模式只改一处；
- **可复现、可 diff**：`python tools/build.py` 重跑一次得到完全相同的产物。

配套的还有 `tools/build_supp.py`（修复与统一补充 Demo）与 `tools/audit.py`（全站静态审计）。

## 四、具体改了什么

### 4.1 双语：从「两段并排」改成「双 DOM + CSS 切换」

原站把中英两段都渲染出来，再用 JS 遍历所有元素加 `hidden` —— 首屏会闪、遍历成本高、且中文读者视觉上被英文段落打断。

**改成**：中英两版同时存在于 DOM，用 `html[data-locale]` + 一条 CSS 规则切换：

```css
html[data-locale="zh"] [data-lang="en"],
html[data-locale="en"] [data-lang="zh"] { display: none !important; }
```

好处：切换零 JS 遍历、无闪烁、首屏渲染前内联脚本就已定好语言、搜索索引和术语表也能按语言分别检索。切换按钮状态、`<html lang>` 属性同步更新（影响读屏发音与断行）。

### 4.2 代码块：从「灰底 pre」升级为「可读的代码」

- 用 `::before` + `attr(data-ln)` 生成行号，**不污染可复制文本**
- 关键行（原作者用 ⭐ 标记的 123 处）加黄色左边条 + 浅底
- 每个代码块加语言标签、关键点计数、复制按钮
- 语法着色基于原有的语义标记做**渐进增强**——禁用 JS 仍是一份可读的 `<pre>`

### 4.3 信息架构：补上「学习导航」这一层

原站直接给内容，学生不知道「这一章要学什么、要多久、学之前得会什么」。新增：

- **学习目标卡**：每章 5~6 条，用「你应该能够……」的可检验句式（共 26 条）
- **前置知识**与**预计时长**
- **概念依赖图**：每章一张分层有向图，讲清「先理解 A 才容易理解 B」。自研约 6 KB 渲染器，**没有为门户页引入整个 D3（省约 280 KB）**
- **术语表**：25 个术语，每个除了「是什么」还写了「为什么重要、容易在哪儿搞错」——名词表最容易变成背了也没用的清单

### 4.4 检索：命令面板式全站搜索

`Ctrl/⌘+K` 或 `/` 唤起。索引 126 条，覆盖章节正文、关键代码、可运行演示、术语表与补充 Demo。索引**按需加载**（没打开过搜索的读者不付这次请求），极简相关度打分：标题前缀命中 +60、词中 +34、正文 +12。

索引一开始只覆盖 5 章正文（86 条），术语表和补充 Demo 一条都没有——可这两处恰恰最该被搜到：术语表就是拿来查的，补充 Demo 是按图形类型排的图例集。结果是搜「视觉通道」「色觉缺陷」「螺旋」全都返回「没有匹配」。现在 25 个术语和 15 个补充页都进了索引，术语卡的 `<li>` 也补了 `id="term-…"`，搜索可以直接落到那一条上。

### 4.5 进度：小节级阅读记录

读过的章节在侧栏打勾、显示百分比；门户页的章节卡显示「继续 · 已读 X / Y」，回到站点时能直接接着看。

### 4.6 演示：从「全部预加载」改成「按需加载」

原站每章的演示代码写在 `lesson.js` 里，进页面就下载、就执行。现在拆成 5 个独立模块 `assets/js/demos/ch0X.js`，**只有学生真的点开「演示」tab 才动态 `import`**。

同时修掉一个原站隐藏 bug：5 章演示键名互相冲突（第 1 章和第 3 章都有 `d-3-1`），因为都挂在全局 `window.DEMOS` 上。抽取时把注册表收进模块作用域，冲突消失。

### 4.7 视觉系统：用设计令牌，且配色本身就是课程内容

- **设计令牌分层**：原始色阶 → 语义令牌 → 组件，共 128 个 CSS 变量。改主题只动语义层。
- **配色采用 Wong 色板**（Nature Methods 2011），色觉缺陷友好。第 3 章正好讲「色彩与色觉缺陷」——**网站自身的配色就是课程内容的示范**，学生在读第 3 章时，正在看的界面就是那个标准。
- **科技感但不过度**：顶栏毛玻璃 + 门户头部用 `linear-gradient` + `mask-image` 做的坐标网格（呼应「可视化 = 坐标系」），章节卡悬停时右上角淡出主色块。所有装饰都 `aria-hidden`，不干扰信息传递。

### 4.8 门户页：让首页自己会说话

改到这里被提了一句「首页全是文字」。查下来根因是构建脚本的一处疏漏（见 4.10 第 7 条），但也确实点出一个设计问题：**这是一门讲可视化的课，门户页却完全靠文字介绍自己**。

于是给每张章节卡片加了一枚**主题微缩图**：

| 章 | 图形 | 想传达的 |
|---|---|---|
| 1 · 数据 | 四列表格，表头着色 | 数据的本质是「带类型的属性表」 |
| 2 · 流程 | 四段节点链 + 箭头 | 数据在阶段之间流动 |
| 3 · 色彩 | 色相带 + 明度渐变带 | 色彩空间的两个基本轴 |
| 4 · 低维 | 散点 + 坐标轴 | 按量级分组、看趋势 |
| 5 · 时序 | 折线 + 面积 | 变量在时间轴上的走势 |

三条实现约束：

1. **纯内联 SVG、构建期写死**（`tools/build.py` 的 `CHAPTER_MOTIFS`）——不发额外请求、不依赖 JS，禁用脚本时图形依然在；
2. **取色一律走 `--viz-*` 令牌**（就是 Wong 色板，明暗两套主题各有提亮版本），线条用 `currentColor + opacity`，因此**切主题时图形自动跟着换**；
3. 只作视觉指引，语义仍由卡片文字承载，所以整体标 `aria-hidden`，读屏软件不被这些装饰打扰。

网格排布上还有个收尾：5 章在 3 列里必然排成 3+2，**右下角空一格**——读者会觉得「还有一章没加载出来」。补法不是把卡片拉宽（宽度一变，微缩图和标题的相对比例就乱了），而是在第 6 格放一块**「速查与延伸」**：术语表、补充 Demo、独立实验三个入口原本只在页面最底部「配套资源」那段文字里各占一行，学生基本走不到。它用虚线边框、不放进度条，一眼能分出「这不是第 6 章」。

**主线图曾经在说反话。** 那张图是 5 个节点排成的一条直线，可导览词里写的是「颜色单独成章、低维与时序并行实战」——图和话互相矛盾。原因是渲染器直接按数组声明顺序给了深度，等于断言「第 4 章要学完第 3 章」。现在改成从依赖边反推层级（`conceptmap.js` 的 `layering()`），实际排出来是三列：`01 数据 → 02 流程 → {03 色彩, 04 低维, 05 时序}`。同时做了**传递约简**（`reduceEdges()`）：`01→03` 这条边既然有 `01→02→03` 可达，留着只会横穿中间那一列的节点。节点里也补了章号，图上的「03」和下方卡片的「03」能直接对上。

**窄屏不能只靠横滚。** 三列的图要 553px，390px 手机上只能在卡片里横向滚动——而横滚没有任何可见提示，读者看到 01、02 就以为图到此为止，三条支线全在屏幕外（章节概念图同样要滚 316px）。所以 <620px 时换成竖排树：一行一个节点、按层级缩进、L 形折线连接（`layoutTree()` / `edgeTree()`），宽度降到 227px，一眼看完。第 2 章那条「交互 → 数据变换」的回指边单独走外侧绕回（`edgeTreeLoop()`），不然会向上穿过中间的兄弟节点。

### 4.9 可访问性与响应式

| 项目 | 做法 |
|---|---|
| 键盘 | 全部交互可达；`:focus-visible` 统一焦点环；命令面板有焦点陷阱；搜索/小节切换/翻章都有快捷键 |
| 跳转链接 | 每页首个可聚焦元素是「跳到主要内容」 |
| 读屏 | 858 个 `aria-*`；概念图、演示区带 `role="img"` + `aria-label`；14 张理论表格补齐 `scope="col"`，表头与单元格可被正确关联 |
| 动效 | 尊重 `prefers-reduced-motion`（5 处），关闭后所有过渡降到 1ms |
| 断点 | 5 档（1080 / 900 / 720 / 640 / 480）。宽表格在窄屏转卡片态，用 `td::before { content: attr(data-label) }` 保留字段名 |
| 触屏 | ≤900px 时图标按钮从 32px 放大到 40px，减少点偏 |
| 打印 | 打印时三个 tab 全部展开——讲义可以直接打印成一叠 |

**还有一个遮挡问题**：「自动导览」胶囊固定在视口底部，390px 手机上正好压住一行正文，而且一直压着——普通滚动改变不了它的位置，除非滚到页面最底部（那里留了空白）。现在向下阅读时收起、向上滚或回到页顶再出现（`shell.js`，用 `data-hidden` 切换位移和透明度）。和手机浏览器收地址栏同一个思路：读的时候让开，要用的时候在。导览进行中不收起，否则解说条会消失一半。

| 15 | 门户页两处 `id="tour-play"` | 页尾「开始导览」按钮点了没反应 | 重复 id，`getElementById` 只返回第一个 |
| 16 | 术语表标题从 h1 直接跳到 h3 | 读屏大纲里 25 个词条没有父级 | 词条标题用了 h3 |
| 17 | 14 张理论表格的表头没有 `scope` | 读屏无法把单元格和表头对应起来 | `<th>` 缺 `scope="col"` |
| 18 | 所有图片没有 `width`/`height` | 图片加载时正文往下跳（CLS） | 构建期没写尺寸 |
| 19 | 全部页面没有 canonical / `og:image` | 分享到群聊里没有预览图 | 抽取外壳时漏了 |
| 20 | 讲义页窄屏多出 4px 横向滚动条 | 手机上整个页面能左右拖动 | 表格滚动容器要做通栏，用 `margin-inline: calc(var(--sp-4) * -1)` 往外拉；但 `.shell` 在 ≤720px 已经把左右留白收到 `--sp-3`，多出的 4px 把页面撑开了 |

**第 11 条值得单独说。** 它是对着「新读者会看到什么」这个假设去测才浮现的：我们自己的浏览器验证一直是绿的，因为前几步点过 tab、`localStorage` 里留下了记忆，恢复逻辑正好走通。**把 `localStorage` 清掉重开，才发现首访读者拿到的是一张空页**——这类 bug 只要开发过程中点过一次 tab 就复现不出来，因此它躲过了此前所有检查。现在验证脚本里那条断言每次都会先 `clearStorage` 再 reload，并且量的是「每节可见面板数 ≥ 1」与「全章正文字数」，不再信任界面看起来有没有东西。

**第 20 条的教训在断言本身。** 那条检查原本写的是 `overflow <= 4`，本意是容忍亚像素舍入；而这处 bug 恰好是每边 4px，**被容差原样吃掉**，一直在报绿灯。现在阈值卡死在 0，并且从「只量 `/lesson-01/` 一个页面」扩成「5 类页面 × 390/360/320 三档」共 15 个组合，失败时会把最右边那个元素一起打出来。有容差的断言等于没有断言。

第 8~10 条暴露的是同一个教训：**验证本身失效**。当时的断言写的是 `mounted > 0 || svg > 0`，而加载中/失败时也会插入一个 `.demo-state` 的 `<p>`——于是「至少挂载了一个元素」恒成立，演示全挂它照样是绿的。现在改成只认 `data-ready="1"`、挂载点非空、无失败请求，并且 5 章逐章跑（第 2 章解析失败而第 3 章正常，只抽查一章必然漏）。同时给 `audit.py` 加了「演示接线错误」这条静态规则：`data-demo-chapter` 必须能落到真实的 `chNN.js`，`data-demo` 键必须在模块里注册过。

修正后做了一轮**防御性加固**：

- `boot()` 里每个模块各自 `try/catch`，一个坏了只影响它自己，控制台直说哪个模块坏在哪——这类「静默级联失效」不该再有第二次；
- 静态审计新增 **`样式未加载`** 检查（见第六节）：把每个页面用到的类，逐个对照「本页实际加载的样式表」里有没有定义。上面第 7 条就是它专治的情况；
- 静态审计另加一组 **结构检查**：重复 id、标题层级跳跃、表头缺 `scope`、代码块里出现裸标签、图片缺尺寸、缺 canonical / `og:image`——第 13~19 条都属于「页面能看、但结构和语义是坏的」，只有静态扫全量文本才发现得了；
- 浏览器验证新增 **`布局成型`** 断言：不去数元素在不在，而是**量容器里出现了多少个不同的左边界**——也就是它到底排成了几列。样式一丢就会掉到 1 列，立刻失败。

三条新检查都做过**破坏性验证**：故意把 `&lt;defs&gt;` 改回 `<defs>`、删掉一个 `scope`、塞一个重复 `id`，确认它们各自都能准确报出来——检查通过不等于检查有效，得先证明它会失败。

### 4.11 三处「保底体验」

教学站点会被各种环境打开：机房老浏览器、打印出来的纸质件、断网、以及老师直接把某一页截进 PPT。下面三件事都是为这些场景做的。

**① 禁用 JavaScript 也要能读。** 章节页的正文分在三个 tab 里（讲解 / 关键代码 / 演示），而 tab 是靠 CSS `display:none` 隐藏的——脚本没跑起来，读者就只能看到一行行小节标题。补一条兜底：没有 `data-tabs` 标记时，三个面板全部展开、tab 条隐藏。

```css
.tab-panel { display: none; }
html:not([data-tabs]) .tab-panel { display: block; }
html:not([data-tabs]) .tabs { display: none; }
```

`data-tabs` 由 `shell.js` 在**确认 tab 真的绑好了之后**才写到 `<html>` 上，所以「脚本加载了但中途出错」也走兜底。实测：禁用 JS 后单章正文从 1208 字恢复到 3782 字。

**② 图片点开看大图。** 课程里的图（Mackinlay 1986 的通道排序图、色彩空间示意）缩在正文宽度里很多细节看不清。用原生 `<dialog>` + `showModal()` 做放大层——ESC 关闭、焦点陷阱、`::backdrop` 全由浏览器提供，不引第三方灯箱。

两个实现细节：判断「这张图值不值得放大」用的是构建期写进属性的 `width`，而不是 `naturalWidth`——图片是懒加载的，视口外的图此刻 `naturalWidth` 是 0，按它判断会把正文图误当成图标跳过。另外 `.img-zoom` 为了居中写了 `display:grid`，这会覆盖浏览器给关闭态 `<dialog>` 的 `display:none`，**关掉的图会继续留在屏幕上**，所以要显式补一条 `:not([open]) { display: none; }`。

**③ 首页补回「关于这门课」。** 重构时整段丢过：理论来源（Card / Mackinlay / van Wijk / Munzner）、设计原则、技术栈、数据集出处。这四块正是学生判断「这门课可信不可信、学完能干什么」的依据，现在用 `<dl>` 语义化排回去，中英双语。

### 4.12 四个章节页长得一样 → 给每章一个身份

翻章时除了标题，五个章节页没有任何差别：同样的黑色小标签、同样的灰色小节编号。读者从第 3 章跳到第 4 章，视觉上等于没动。

改法是给每章一个身份色（直接用 Wong 色板的 `--viz-1..5`，和图里用的是同一套），只用在这一层：

- 章首右上角一枚 148px 的章号水印（`03`），透明度 11%，压不过程度正文；
- 章首一排关键数字：`8 个小节 / 55 分钟 / 28 处关键代码 / 6 项学习目标`，数字用等宽字体放大到 24px、染色，单位跟在后面。读者一屏之内就能判断「这章多长、有多少代码」；
- 小节编号的底色由身份色 `color-mix` 出来（不支持 `color-mix` 的浏览器退回原来的品牌色）。

原来「学习目标」区右上角那行小字（项目标 / 分钟 / 小节 / 代码）和新的数字条完全重复，一并去掉；目标清单在 ≥900px 时改成两列，六条目标从占半屏变成一次扫完。

### 4.13 术语互链：正文 ↔ 术语表

正文里第一次出现「视觉通道」「阿基米德螺旋」时，读者往往正需要它的定义，而术语表在另一个页面、只能靠搜索找到。现在两处连成了一张网：

- **正文 → 术语表**：`tools/build.py` 的 `link_terms()` 在每个「讲解」面板里找术语的首次出现，链到 `glossary.html#term-<id>`。每小节最多 3 处；
- **术语表 → 正文**：每条词条下方反向列出「出现在 3.1 4.2 5.3」，链接直达小节锚点。

三条约束：只在文本节点上动手（代码块、已有链接、标题一律跳过——把代码里的 `channel` 换成 `<a>`，学生复制出来就不再是能跑的代码）；一个术语全文只链一次；别名也算（正文写「定序」，词条叫「序数尺度」，靠 `glossary.json` 的 `alias` 字段接上）。

### 4.14 章末自测：把「读完了」变成「会了吗」

每章末尾 4 道单选题，选完立刻判分：正确项标 ✓、选错的标 ✕，下面给解析，解析末尾是回到对应小节的链接（「复习 3.2 colormap 三类选择」）。

几个刻意的选择：**不做统一提交、不记分、不上传**——这是自查工具，不是考试，选完立刻反馈才能让读者的注意力留在那道题上。对错除了颜色还叠了 ✓ / ✕ 图标：第 3 章自己就在讲色觉缺陷，这里更不该把「对不对」只编码成红绿两色。判分文案按当前语言即时生成，切中英文时会重画。

### 4.15 让页面动起来，但不拿内容冒险

动效只做两件事：滚动到某一段时轻轻浮现（12px 位移 + 淡入）；概念图的节点依次浮上来、连线随后淡入。有三条硬约束：

1. **初始隐藏由脚本打标记**（`html[data-motion="1"]` 之后 CSS 才生效）。样式表里默认 `opacity: 0` 的写法，一旦脚本没跑，整页正文就是空白；
2. **判定用位置，不用 IntersectionObserver 的进入事件**。跳到页尾（End 键、锚点、搜索结果直达）时，中间那些段落只是被「跳过去」了，从未与视口相交，IO 不会为它们触发——它们会永远停在 `opacity: 0`。现在只要元素顶部越过视口下沿就放行，不管它是滚过去还是跳过去的；
3. **打印媒体下强制可见**，否则没滚到的段落会印成白纸。

`prefers-reduced-motion: reduce` 时完全不启用。三条都有断言看着（见第六节）。

### 4.16 演示从「能看」到「能玩」：参数真的可以调

原站的演示大多是「点一下，出一张图」——读者只能看结论，不能验证。改造先从第 3 章的 colormap 演示开始：同一组 50 州谋杀率数据摆在那儿，读者可以一键在 Viridis / Blues / Turbo / RdBu 之间切换，色带实时重画，下方一句判语跟着翻（顺序型 ✓ / 彩虹与发散型 ✗）。

这一改反而暴露了一个藏了很久的 bug：`#seq-bar` 把归一化后的 `t`（0–1）喂给了 domain 为 `[0, 350]` 的 `scaleSequential`，于是 50 个格子几乎全部落在 `t≈0` 那一端，**整条色带是一色到底的死紫色**——看上去就像「这些州的数据没差别」。而它「能渲染、不报错、有 50 个格子」，此前所有断言都是绿的。现在这一节统一用 interpolator（`t → 颜色`），并新增断言：量不同颜色的个数，而不是子元素个数（`seqColors: 50`）。

顺带把演示里写死的 `color:#dc2626` 收进 `--err-600` 令牌——深色主题下同一个红必须换一档才读得清，写死就永远只有一套。

### 4.17 d3 从 CDN 搬进仓库：27 个演示不再看网络脸色

这是验证过程中被逼出来的改动。原站（以及上一版重构）从 jsDelivr 的 `+esm` 入口取 d3——那个入口**不打包**，浏览器实际要发 40 多个模块请求（`d3-array`、`d3-color`、`d3-delaunay`…）。网络一抖、或遇到会拦第三方脚本的网络，演示区就永远停在「正在加载演示…」；`supplementary/tableshow.html` 更是直接报 `d3 is not defined`。

现在 `assets/js/vendor/` 里有三个本地文件：

| 文件 | 用途 | 体积 |
|---|---|---|
| `d3.esm.js` | 5 章演示模块（`import * as d3`） | 277 KB |
| `d3.min.js` | 补充 Demo / 独立实验（经典 `<script>`） | 274 KB |
| `d3-regression.min.js` | 回归示例的插件 | 8 KB |

`tools/build.py` 在抽取演示模块时会把 import 强改为本地路径，`tools/build_supp.py` 的模板也一并改掉——重新构建不会退回 CDN。收益是两条：**首屏少 40 次往返**，以及**断网也能把 27 个演示跑完**。

### 4.18 知识图谱：节点可以拖着看

参考站（CVClass）最值得借鉴的一处：图不是一张固定插图，而是可以拨开的。

现在章节页的概念图与门户的课程主线都能拖动节点，松手记住位置，切主题 / 切语言 / 转屏之后还在。实现上有三个不显然的点：

- **坐标要过 `getScreenCTM().inverse()`**。图靠 `viewBox` 自适应容器宽度，屏幕 1px ≠ SVG 用户单位 1px。直接拿 `clientX` 差值当位移，在非 1:1 缩放下就是「鼠标走了 100，方块只走 76」。
- **位移只写 `n.ox / n.oy`，绘制时叠加到 `<g transform>`**。切主题会整图重绘，直接改 `n.x / n.y` 会被新布局覆盖。
- **横排与竖排分开记偏移**。两套坐标系宽高差好几倍，一份偏移通用不了。`offKey` 的第三个参数是模式字符串而不是布尔 —— 传布尔时 `"h"` 也是真值，会静默地全算成竖排（这个 bug 真的写出来过，表现是「切主题后节点弹回原位」）。

细节：拖动时把节点 `appendChild` 到末尾提到最上层（否则被拖的会被别的节点盖住，像消失了）；限制在画布内（拖出去就抓不回来）；双击单个节点复位；挪过之后 figcaption 里才出现「恢复布局」。`touch-action: none` 加在节点上，手指落在节点上就是拖节点而不是滚页面。

### 4.19 学习路径：五章不必都读

参考站用一张「关卡地图」表达路线。这里不需要那么重，但「该按什么顺序读」确实没人说过。

门户新增三条路线：**零基础从头走**（01→02→03→04→05）、**会写 JS 想快点出图**（01→02→04，跳过色彩与时序）、**只补色彩或时序**（01 打底 → 03 或 05）。每条路线是一列带连接线的步骤，每步一句「这一章在这条路线上要看什么」。

步骤复用站内已有的阅读进度：某章读到 100%，序号圆圈就变成对勾。没有第二套状态。

### 4.20 首屏背景：一块会呼吸的「可视化工作台」

参考站用一张 hero 大图压场。这里换成**内联 SVG 的工作台**：左边一块大的观测面板（网格 + 散点 + 趋势线 + 一个 P95 高亮点），右边上下两块小的——分布直方图和节点关系图，中间用流动虚线连起来，暗示「观测 → 分布 → 关系」这条分析路径。三块面板轻微错相位浮动，连线上有一串光点朝箭头方向走。

第一版做成了竖着叠三块（620×480），实测会压住下面的统计条：`27`、`123` 这几个数字正好浮在图表上，看着像排版事故。改成 640×368 的横条、顶端对齐 h1 上方、底边卡在统计条之前，问题才消失。**这类问题只能量，不能靠眼睛估**——所以断言里直接比 `art.getBoundingClientRect().bottom <= stats.top`，并在 1440 / 1200 / 1024 三档都跑一遍。

好处：跟着主题变量换色、高分屏不糊、不多一个几百 KB 的请求，断网也在。动画只改 `stroke-dashoffset` 和 `translate`，不碰布局；`prefers-reduced-motion` 下全部停掉，打印时整块隐藏。

### 4.21 「切英文没反应」：一个从构建期就错了的 bug

用户报的是首页语言按钮点了没变化。查下来是三处叠在一起：

1. **门户页的标题、副标题、统计条、使用说明全是硬编码中文**，只有按钮是双语的。语言状态确实切了，页面看着纹丝不动。
2. **小节英文标题从来没生效过**。`RE_H2` 捕获的 key 已经是 `sec-01-1.title`，代码又拼了一次 `.title`，于是 `ZH.get()` / `EN.get()` 两边都取不到，静默退回中文原文 —— 27 个小节、5 章的侧栏目录、章节卡片标签全是中文。修法是去掉那次重复拼接。
3. **语言按钮在单语页面上是死按钮**。判断「这页有没有英文版」原来查的是整页 `[data-lang="en"]`，而顶栏品牌、面包屑本身就是双语的，所以永远为真。改成只看 `main`，没有英文正文的页面把 EN 置灰并给出 `title` 说明。

顺带把讲义页做成了真正双语：中英两版 markdown 都渲染进同一页，英文锚点加 `-en` 后缀（否则两版 h2 的 id 相同，英文模式下点目录会跳到被隐藏的中文标题上）。术语表在英文模式下把英文词条升为主标题，中文名隐去。

> 已知缺口：27 个演示内部的解说文案仍是中文。正文、标题、导航、术语表、讲义都已覆盖，演示文案体量大、且大量嵌在 D3 代码里，留待后续。验证脚本会单独计数并打印这个数字，不藏起来。

### 4.22 去掉「预计时长」

章首统计条与章节卡片的「约 N 分钟」都删了。阅读速度差好几倍，写死的数字对谁都不准，反而让人先打退堂鼓；「这一章有多少东西」用小数、演示数、代码点数表达更诚实。

### 4.23 知识图谱：让连线「流」起来，让邻居「亮」起来

参考站的知识图谱是 ECharts 力导向图，节点可以拖、可以缩放漫游。这里没有引入 ECharts——课程的概念图是**分层依赖图**，层级本身是教学信息（谁是谁的前置），力导向会把这条信息打散。

补的是两件更轻的事：

1. **每条边画两层**。底层是实线 + 箭头，保证「谁指向谁」在打印和旧浏览器上都清楚；上层是同形状的虚线，靠 CSS 让 `stroke-dashoffset` 匀速后退，看上去是一串光点沿箭头方向流。两层共用同一个 `d`，拖动时同步重算。周期取 `dasharray` 的整数倍（6+14 走 -40，5+9 走 -42），否则每圈结尾会跳一下。
2. **悬停聚焦**。鼠标停在一个节点上，只留它、它的直接上下游和它们之间的连线，其余淡出。图不到十个节点看着不乱，但读者一旦想问「这个概念是从哪来的」，就需要把那条链单独拎出来。触屏不做这个——`pointerenter` 在手指抬起后不会配对 `pointerleave`，点一下整张图就一直是暗的。

### 4.24 门户的知识图谱：从「章节目录」到「知识点网络」

4.23 做完之后，门户上那张图仍然只是**五个章节方块**。它回答的是「先学哪章」，不是「这门课有哪些知识点」——按知识库的标准，它是目录，不是图谱。这一轮把门户那一块整个换掉：

**数据**。新增 `tools/data/kg.json`，为 26 个知识点各写一句话总结、标签、所属小节，再补 10 条跨章依赖（`01.n3 尺度×通道 → 02.n3 视觉映射`、`02.n2 数据变换 → 04.n1 宽转长` 这类真正有教学依据的边）。构建时与 `chapters.json` 的 `concept.nodes` 逐条核对 id、名称、小节号，任何一边改了另一边没跟上就**直接构建失败**——图和正文悄悄脱节是最难发现的问题。

**交互**。默认展开第 1 章：一进来就有五个知识点围着「数据」这颗章节点，右侧是章节总结与四格统计。点章节展开/收起，点知识点看它的一句话总结和「跳到该节」，跨章边把五章连成一张网。画布可平移缩放，节点可拖动，`Esc` 与点空白回到总览。

**性能**。d3 用动态 `import("./vendor/d3.esm.js")`，并且等 `IntersectionObserver` 报告图谱进入视口才加载。门户是读者第一个打开的页面，不该为一个第二屏的图先付 280 KB。

四个坑，都是「看着能跑但不对」的那种：

1. **归属边不能省**。第一版只有 root→章 和知识点之间的边，展开一章后那几颗知识点和章节点之间**没有任何连线**——力导向把子图当成独立分量，斥力一路把它们推到画布外。补上「章→知识点」的 `member` 边（很淡，无箭头）才收拢回来。
2. **root 必须钉在中心**。它是这张图的锚点；让它跟着力跑，每展开一章整张图都漂一次，读者会以为换了一张图。
3. **越界判断要过 zoom transform**。`bbox()` 给的是 SVG 用户坐标，画布尺寸是屏幕像素，中间差一个缩放 + 平移。第一版直接比较，结论永远是「越界」——于是 `fitView` 被反复触发，还查不出为什么图一直在缩。
4. **选中不该压暗别人**。最初 hover 和选中共用一套 `is-dim`，点开一个知识点，图上另外三十个标签全消失，读者看到一堆没有名字的圆点。现在 hover 才聚焦，选中只高亮；另外加了语义缩放——缩到读不清字（或一次摆上十几个知识点）时概念标签让位、只留章节名，选中哪一章就把它的成员标签放回来。

留白也踩了一次：`fitView` 的 padding 原本按 SVG 单位给（56），图缩到 0.58 时那 56 单位只剩 32 像素，标签直接贴到画布边上。改成按屏幕像素算，全展开的缩放从 0.58 回到 0.73，标签也不再蹭边。

验证脚本相应改了三条：装配完成且默认展开一章、点知识点换详情并给出小节锚点、全部展开后 32 个节点零越界且标签自动让位。原来那条「主线按依赖分层」的断言随组件一起退休。


### 4.25 门户的信息架构：学习路径为什么必须排在知识图谱之前

4.24 把「课程主线」换成了知识图谱，代价是**学习路径被挤到了第三屏**。图谱本身有八百多像素高，它前面还压着首屏；门户又没有导航，读者往下滚第一眼看到的是图，于是合理地以为路径被删掉了。

问题不在路径写得好不好，在于**两块内容的分工没写清楚，位置也没按分工排**：

| | 回答的问题 | 性质 |
|---|---|---|
| 学习路径 | 我该按什么顺序学？ | 行动 |
| 知识图谱 | 这门课里有什么？谁依赖谁？ | 查阅 |
| 全部章节 | 具体某一章在哪？ | 入口 |

行动在前、查阅在后。参考的 CVClass 也是这个顺序（导航里「学习路径」在「知识图谱」之前）。所以这一轮把 `#paths` 提到 `#kg` 前面，并且**给门户补上它一直缺的东西——页内导航**。

**顶栏那排导航**（学习路径 · 知识图谱 · 全部章节 · 怎么用）替掉了门户原来的面包屑。面包屑在门户只有「课程门户」一项，回答的是「我在哪」，而读者真正需要的是「往哪去」。三条约束：

1. **顺序必须等于版块在页面里的物理顺序**。对不上，读者点一次发现往回跳，第二次就不信了。这条写进了断言（`NAV_TARGETS`）。
2. **滚动时高亮跟着走**。`requestAnimationFrame` 节流，判定线放在顶栏下沿再往下 32px——标题刚碰到顶栏就算进了这一块。
3. **窄屏要能收**。1080 以下只留「学习路径 / 知识图谱」两项，720 以下整排隐藏：顶栏还要放搜索、主题、语言，挤在一起谁都不好点。

**学习路径补了进度**。原来步骤序号上的对勾由 `shell.js` 统一写 `data-progress-value`，但它只在 100% 时才有视觉差异——刚读了两章的人看到的是一条完全静止的路径。现在卡片头部多一行「已读 m / n 章」：

```js
steps.forEach(function (st) {
  var scope = st.getAttribute("data-progress-scope");
  var total = parseInt(st.getAttribute("data-progress-total") || "0", 10);
  var n = 0;
  for (var k in map) if (map[k] && k.indexOf(scope) === 0) n++;
  if (n >= total) done++;
});
```

一章没读时**不显示**：写「已读 0 / 5」不是信息，是压力。

顺带修了三个小东西：

- 门户顶栏原来是带侧栏开关的，`aria-controls` 指向不存在的 `#sidebar`，点下去毫无反应。没有侧栏就不该有开侧栏的按钮，`topbar()` 加了 `sidebar=False`。
- `.topbar__actions` 原来靠中间的弹性项（面包屑）顶到右边。窄屏下面包屑 `display:none`，中间没人撑开，右边那组按钮就贴着品牌名。改成 `margin-left: auto`。
- 480 以下品牌名整段隐藏，门户顶栏只剩一个色块图标。门户没有侧栏开关，比章节页少占 40px，380 以上其实放得下——加了一条 `min-width: 380px` 的例外。

新增四条断言：版块顺序与导航一致、滚到图谱时高亮跟随、没读过时不显示进度、读过之后数字与对勾都对。断言尾行的计数原来硬编码在 `interact` 数组上（一直停在 23，而 README 写 25），这次拆出 `sideChecks / sidePass` 一起汇总，尾行不再说谎。

## 六、怎么确认改对了：三层验证

重构最容易出现「静态看起来没问题、点开是坏的」。所以做了三层，且都可重复执行：

**第一层 · 静态审计** `python tools/audit.py`

检查 8 类问题：断链、站点根绝对路径、外部 CDN 可达性、编辑器残留与非法 HTML、图片 `alt`、内容完整性（小节数/演示数与元数据是否对得上）、**样式覆盖**（页面用到的类，是否真有「本页加载了的」样式表去定义它）、以及**文档结构**（重复 `id`、标题层级跳跃、表头缺 `scope`、代码块里出现裸标签、图片缺尺寸、缺 canonical / `og:image`）。

其中三条规则是踩坑后加的：
- 扫描前先挖掉 HTML 注释、`<pre>` 代码示例块、JS 注释 —— 否则正文里的 `from 'a table' to 'a chart'` 会被当成 import 说明符，代码示例里的 `from 'd3-regression'` 会被当成真实依赖；
- 运行时路径的解析基准要按**加载该脚本的页面**算，并沿 import 图传播 —— 否则 `d3.csv('./data/x.csv')` 会被误判成断链；
- 样式覆盖必须拿「本页实际加载了哪几张样式表」当基准。只判断「这个类在全站有没有被定义过」是不够的：门户页漏引 `portal.css` 那次，`.chapter-card` 在 `portal.css` 里定义得好好的，问题恰恰是这个页面没加载它。

**第二层 · 浏览器渲染** `node tools/verify_render.mjs`

无头 Chrome 逐页打开 **35 个页面**，抓五类只有运行时才暴露的问题：控制台报错 / 未捕获异常、请求失败、DOM 断言（该出现的元素真的出现了）、内容断言（日历要真的画出 ≥1400 个格子，而不是「有个空 svg」）、以及**布局成型断言**。

最后一条的思路值得单说：**它不去数元素在不在，而是量一个容器里出现了多少个互不相同的左边界** —— 也就是这个栅格实际排成了几列。样式一旦丢失，任何多列容器都会掉到 1 列，断言立刻失败。门户页那次塌版就属于这一类：`.chapter-card` 一个不缺，但全在同一列上。

> 当前结果：**35/35 页面完全干净，0 报错、0 失败请求；门户页实测章节网格 3 列、统计条 4 列、使用说明 4 列，5 枚微缩图共 48 个图形，课程主线图 5 列 9 节点（不是一章一列）。**

**第三层 · 交互验证**（同一脚本内）

23 项端到端断言：演示 tab 触发动态 `import` 并渲染（5 章共 27 个挂载点全部 `data-ready="1"`）、**演示不依赖站外 CDN（站外请求 0，本地 vendor 命中 1 次）**、搜索出结果（24 条）、主题切换、中英双 DOM 切换（英文可见且中文全部隐藏）、概念图渲染（18 个图形）、**阅读进度写入并让本章侧栏显示 100%**、**首访（先清空 localStorage）每节都有可见面板且全章正文 4119 字**、**图片可点开放大再关闭**、**章末自测答对/答错都有解析且回查链接落点存在**、**正文术语能跳到术语表词条**、**色板切换真的换了颜色（50 个格子 50 种颜色）**、**减弱动效时不留隐藏段落**、**课程主线按依赖分层（列数必须少于节点数）**、**概念图每条边都有流动虚线且悬停能聚焦邻居（6 条边 = 6 条流动层 = 6 个箭头）**、**首屏工作台在 1440/1200/1024 三档都不压统计条、不出视口，1020 以下隐藏**、**知识图谱节点拖完切主题不弹回（拖后 89px，切主题后仍 89px，复位归零）**、**门户三条学习路径排开且 11 个步骤都指向真实章节页**、**切英文后正文无中文残留（演示区单独计数）**、**讲义可切英文且目录锚点指向带 `-en` 后缀的英文正文**。

另有窄屏与打印媒体的回归检查：**6 类页面 × 390/360/320 三档，18 个组合全部零横向溢出**，且正文里的关系图容器**自身**不允许出现内部横滚（`scrollWidth - clientWidth === 0`）；汉堡按钮 40×40 可点、侧栏默认收起；打印时三个 tab 全部展开。

> 断言的口径也在收紧。早期那条「无横向溢出」写的是 `overflow <= 4`（想容忍亚像素舍入），结果把第 20 条那个每边 4px 的真 bug 一并容掉，一直报绿。**有容差的断言等于没有断言**——现在卡死在 0，失败时连「最右边那个元素是谁」一起打出来。

## 七、遗留与取舍

诚实说明几处**有意没做**的事：

1. **补充 Demo 里的 9 处旧式（非 module）`<script src>`** 保留了。这些页面用「全局函数 + 顺序加载」，页内自洽、能跑。改成 ES Module 要动作者的数据管线（相互依赖的全局函数），**风险大于收益**。审计脚本把它登记为「遗留说明」而非缺陷（它们现在指向的是本地 `assets/js/vendor/d3.min.js`，不再外连）。
2. **三个 CDN 引用已全部收进仓库**（`d3js.org`、jsDelivr 的 `+esm`、`unpkg` 的 d3-regression）。原样保留的代价是「网络一抖演示区就空白」，实测确实发生过，所以这条不再算取舍，见 4.17。
3. **`d3-regression` 的脚本顺序**：实测两个 UMD 包的挂载方式不同——d3 v7 是 `window.d3 = window.d3 || {}`（叠加，安全），d3-regression 是 `window.d3 = {}`（**无条件覆盖**）。所以必须先加载插件、再加载本体，反过来会报 `d3.scaleLinear is not a function`。
4. **仓库里另附的讲义 PDF** 原样保留，未改写。
5. **未加视频**（按要求：服务器存储空间有限）。

### 线上地址与部署方式

仓库根目录就是站点根，**无需任何构建步骤**：

```bash
git push origin main      # 推送后 GitHub Pages 自动重建，约 1 分钟生效
```

站点配置（已启用）：Source = `main` 分支 `/ (root)` 目录，强制 HTTPS。

### 关于 404 页的一个真实坑

GitHub Pages 把这个文件部署在**站点根**，但浏览器地址栏里保留的仍然是**没找到的那个路径**。
于是页面里所有相对地址都会被按缺失路径解析 —— 访问 `/a/b/c/` 时，页面写的
`assets/css/tokens.css` 会变成 `/a/b/c/assets/css/tokens.css`，favicon、样式、脚本全部 404，
**页面变成一张没有样式的裸页**。

这个坑本地预览测不出来（本地站点根就是 `/`），是上线实测才暴露的。修法是让 404 页在
`<head>` 最前面做一次同步探测，算出真正的站点根写成 `<base>`，此后文档里所有相对地址
自动按正确基准解析，不用逐个去改。

`tools/verify_live.mjs` 就是为这件事写的 —— 部署后跑一次，确认 404 页在子路径下样式正常。
当前结果：**11/11 全部通过**。
